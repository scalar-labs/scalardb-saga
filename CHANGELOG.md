## [v3.20.0] - 2026-10-29

### Enhancements

- First GA release of ScalarDB Saga, which coordinates a transaction that spans several services as a saga. Each step calls a service, and when a step fails, the steps already completed are undone by their compensations, in reverse order. A `TCC` mode reserves resources first and confirms them only once every reservation succeeds. Saga state is stored in your database through ScalarDB, so a saga that a stopped server left unfinished is recovered.
- Sagas are defined in JSON or YAML, with each step calling an HTTP service. A step can wait for a slow participant, which reports back through a callback URL.
- The ScalarDB Saga server, shipped as the container image `ghcr.io/scalar-labs/scalardb-saga-server`, runs sagas behind a REST API and a gRPC API. It authenticates callers by API key or JWT, serves TLS on both, and reloads definitions, service files, and certificates without a restart. `--validate-config` checks a configuration before it ships.
- The Java client SDK, `scalardb-saga-java-client-sdk`, runs on Java 8 or later. In embedded mode, `scalardb-saga-core` runs the engine inside a Java 25 application instead, where a step can also be a Java class.
- Operators can list sagas, and recover, force-complete, or reset a saga that the engine escalated, through an admin API. Every error carries a `DB-SAGA-` status code, listed with its cause and the action to take in `guides/scalardb-saga-status-codes.md`.
